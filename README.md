# UMD_Converter

把**文本型 UMD 电子书**转换成 EPUB 的命令行工具。

UMD 是早期国内手机阅读器（掌上书院等）使用的电子书格式，现在很多阅读器已经不再支持，
而 EPUB 几乎被所有阅读器支持。本工具负责这两种格式之间的转换。

## 这个转换器不需要额外依赖

- **只用 Python 标准库**：`zlib`、`zipfile`、`html.parser`、`argparse`、`uuid`、`urllib`。
- **不需要** `pip install` 任何第三方库，**不需要** Calibre、Kindlegen、LibreOffice 等外部程序。
- **默认转换过程不联网**，可以完全离线使用；唯一的联网功能是可选开关
  `--fetch-illustrations`（去轻小说文库抓插图，见下文），不加这个开关就不会有任何网络请求。
- 唯一前提：机器上有 Python 3（开发与验证使用 Python 3.11，代码兼容 3.8 及以上）。
  Windows 上没有 Python 的话，装一次官方 Python 即可，之后本工具不再需要任何东西。

## 为什么写它

**轻小说文库**（Wenku8）等站点提供的 UMD 打包文件，放进第三方小说阅读器
（静读天下、多看、微信读书、Apple Books 等）时经常无法直接打开或排版错乱。
本工具把 UMD 转成通用性最好的 EPUB，方便把这些书直接导入阅读器阅读。

## 为什么没有漫画功能

UMD 的**漫画型**（图文页）没有被支持，原因是：

1. UMD 格式从未公开官方规范，现存可查的文档与实现只描述了文本型；
2. 能查到的开源解析器都明确不支持漫画型，例如 `shawcn/UMD_Project` 的 Kotlin 实现与
   `linpinger` 的 Go 实现，遇到非文本类型都直接抛"不支持"；
3. 找不到可用于验证的真实漫画型样本，缺少样本就无法保证解析结果正确。

因此本版本只处理文本型 UMD。遇到漫画型文件时会**明确报错**（退出码 4），
不会产出一个能打开但内容是坏的 EPUB。

## 插图：UMD 里为什么没有，怎么补回来

**UMD 本身不含插图数据。** 站点的官方 TXT / UMD / JAR 打包都不带图片，UMD 的正文里只有
`（插图003）` 这样的**文字占位符**——那是书源自己标注的"插图应该在这里"的位置，
不是广告，也不是可提取的图片引用。实测把整个 UMD 逐字节扫一遍，JPEG/PNG/GIF 出现 0 次，
正文解压后的长度与文件里声明的正文长度一字节不差，没有任何夹带图片的余地。

真正的插画只存在于站内**每卷末尾的"插图"章节页**的 HTML 里。所以要把插图补进 EPUB，
只能联网去抓：

```bat
:: 抓插图并写进 EPUB(默认关闭, 加了才会联网)
python umd2epub.py 3943.umd --fetch-illustrations

:: 文件名不是书号时手动指定; 图片会缓存, 中断后重跑不会重复下载
python umd2epub.py 我的小说.umd --fetch-illustrations --book-id 3943 ^
    --illustrations-cache D:\cache\3943 --net-delay 2
```

抓取逻辑（对应站内真实结构）：

| 用途 | URL |
| --- | --- |
| 目录页（分卷 + 每章链接） | `https://www.wenku8.net/novel/{书号//1000}/{书号}/index.htm` |
| 插图章节页（该卷全部插画） | 目录页里标题为"插图"的章节链接，例如 `/novel/3/3943/163538.htm` |
| 图片本体 | 写在插图页 HTML 里的 `src`，例如 `https://pic.777743.xyz/3/3943/163538/201390.jpg` |

- 书号默认取输入文件名里的纯数字（`3943.umd` → `3943`），可用 `--book-id` 覆盖。
- 抓到的图片按卷放进 UMD 里对应的 **"第N卷 插图"章节**——UMD 自带这些空章节，位置是确定的；
  正文里的 `（插图NNN）` 占位符保持原样，不做猜测性的原位替换。
- 图片以内容嗅探判断真实格式（站点声明的类型字节并不可靠），统一放进 EPUB 的 `Images/` 目录。
- 站点对缺少 `Sec-Fetch-*` 请求头的客户端返回 403，并且会限速（429），所以本工具发送
  浏览器风格请求头、串行抓取、按 `--net-delay` 间隔请求，遇到 403/429/5xx 会退避重试。

**须知**：插图版权属于出版社与作者，抓下来的图片请只用于自己已购书籍的个人阅读，
不要再分发；站点有限速，别把 `--net-delay` 调得太小，抓一整本（几十张、单张数百 KB）
通常需要十几分钟。抓取失败不会影响转换本身：会打印提示，并按无插图继续生成 EPUB。

## 安装与运行

不需要安装，直接把仓库下载/克隆到本地即可。

```bat
:: 转换一本, 输出到同目录同名 .epub
python umd2epub.py 我的小说.umd

:: 指定输出文件
python umd2epub.py 我的小说.umd -o D:\books\我的小说.epub

:: 批量转换(通配符由命令行展开)
python umd2epub.py *.umd

:: 只解析并打印信息, 不写文件
python umd2epub.py 我的小说.umd --dry-run

:: 也可以作为模块运行
python -m umd2epub 我的小说.umd
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `输入.umd` | 一个或多个 UMD 文件 |
| `-o, --output` | 输出文件或目录（只有单个输入时可用；给目录时自动用原文件名 + `.epub`） |
| `--force` | 覆盖已存在的输出文件（默认不覆盖） |
| `--dry-run` | 只解析并打印书名、作者、章节数、是否走兜底，不写文件 |
| `--title` / `--author` | 覆盖 UMD 里读到的书名 / 作者 |
| `--lang` | EPUB 语言标记，默认 `zh` |
| `--split-chars N` | 单个 XHTML 的最大字符数，超出则在段落边界分片，默认 20000，`0` 为不分片 |
| `--no-cover` | 不写入封面 |
| `--fetch-illustrations` | 联网到轻小说文库抓取插图（默认关闭，不联网） |
| `--book-id N` | 轻小说文库书号，默认取输入文件名里的纯数字 |
| `--illustrations-cache DIR` | 插图缓存目录，默认在输入文件旁建 `.umd2epub-illustrations` |
| `--net-delay SEC` | 抓插图时每次请求的间隔秒数，默认 2.0（站点有限速） |
| `--quiet` | 只输出错误 |
| `-v, --verbose` | 输出更多解析细节 |
| `--version` | 版本号 |

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 其它错误（读文件、写文件失败等） |
| 2 | 命令行用法错误 |
| 3 | 不是 UMD 文件，或文件损坏 |
| 4 | 不支持的 UMD 变体（漫画型） |
| 5 | 输出文件已存在（加 `--force` 覆盖） |

批量转换时，单个文件失败不会影响其它文件，最后打印汇总，并以最严重的错误码退出
（严重程度：1 > 3 > 4 > 5）。

## 没有章节结构时怎么办

部分 UMD（尤其是被重新打包过的）缺少章节偏移表或章节标题表。这种情况下本工具不会失败，
而是**把整篇正文作为单章输出**，并在解析时打印提示说明降级原因，例如：

```
提示: 无章节结构, 已整篇作为单章输出: 缺少章节偏移表(0x83)与章节标题表(0x84)
```

正文内容不会因此丢失；如果单章太长，可配合 `--split-chars` 自动分片，避免阅读器打开
一个几十万字的 XHTML 文件。

## 已识别的 UMD 结构

转换器按下面的结构读文件（已用真实 UMD 文件核对）：

```
功能块  0x23 | 功能ID | - | - | 块长(1 字节) | 负载(块长 - 5)
数据块  0x24 | 数据ID(4 字节小端) | 块长(4 字节小端, 含 9 字节头) | 负载(块长 - 9)
```

- 元数据：书名、作者、年/月/日、分类、出版社、发行商；
- 正文：若干 zlib 流，按文件出现顺序拼接，UTF-16LE 编码，段落分隔符 `U+2029` 会被还原成换行；
- 章节：`0x83` 指向章节偏移表、`0x84` 指向章节标题表、`0x81` 指向正文块 ID 列表；
- 封面：`0x82` 给出图片类型与数据块 ID，实际格式按图片字节内容识别。

## 已知限制

- 只支持文本型 UMD，不支持漫画型。
- 带加密内容（`0xF0` CDS KEY 等）的 UMD 可能解析失败，会以退出码 3 报错。
- 少数变体的正文块没有压缩，本工具会按原始数据使用并打印提示。
- 输出的 EPUB 为 EPUB 2.0（OPF 2.0 + NCX），兼容性优先；工具做了 ZIP/OCF/XML/XHTML 层面的
  结构自检，但不等于通过 `epubcheck`，个别阅读器的显示效果建议实际试读确认。
- 封面只在 UMD 内嵌了图片时才会写入。
- 插图功能依赖站点当前结构：域名、章节编号、限速策略变化都可能导致抓取失败；
  失败时只会打印提示并继续生成无插图的 EPUB。
- 正文里的 `（插图NNN）` 占位符会原样保留，插画统一放在每卷的"插图"章节；
  抓取不到对应卷时会跳过该卷。
- 抓插图很慢（单张数百 KB），大书建议配合 `--illustrations-cache` 让它断点续传。

## 自测

```bat
python -m unittest discover -s tests -v
```

测试全部使用内存中合成的 UMD 样本，不需要任何外部文件、也不联网，覆盖：正常章节解析、封面提取、
无章节块兜底、偏移表与标题表数量不一致、缺少正文块列表、非 zlib 正文块、漫画型与损坏文件
的退出码、EPUB 结构自检、超长章节分片、插图章节打包成图片页、抓取结果按卷挂载、
抓取失败只告警不中断、命令行端到端。

## 目录结构

```
UMD_Converter\
├─ umd2epub.py              命令行入口(python umd2epub.py 书.umd)
├─ umd2epub\
│  ├─ umd.py                UMD 解析(含无章节块兜底)
│  ├─ epub.py               EPUB 打包与 XHTML 归一化
│  ├─ convert.py            单文件转换编排(可被其它界面复用)
│  ├─ wenku8.py             选修: 联网抓取轻小说文库插图
│  └─ cli.py                命令行参数与输出
└─ tests\test_conversion.py 自测
```
